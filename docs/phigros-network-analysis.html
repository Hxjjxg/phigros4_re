结论先行

Java 层确实有两套完整的 WebSocket 收发栈，但没有一个被游戏自身调用。它们分别是 TapTap TDS 自带的 Java-WebSocket（RFC6455 全实现），以及被 shade 重打包进防沉迷模块的 OkHttp 3。两者在 classes.dex 里都是零调用点。

游戏真正的实时通道在 C#/IL2CPP 层：LeanCloud Realtime（LeanCloud-CSharp-SDK/1.0.3），底层包 System.Net.WebSockets.ClientWebSocket。

但这对你是个好消息——那套 Java-WebSocket 是自包含的、可独立驱动的。要跟自己的外部服务器收发 WS，直接复用它即可，零移植成本。走 方案 A。

三层执行栈

图 1 — 两条互不相干的网络路径。虚线为唯一的 Java↔C# 通路。

关键认知：这两条路径彼此独立。Java 层的 WS 栈不依赖游戏状态就能工作，这正是方案 A 成立的前提。

04

Java 层：两套 WebSocket

4.1 可用 com.tds.common.websocket

这是完整移植的 Java-WebSocket（RFC6455），客户端和服务端都在。

  • 协议栈齐全：drafts/Draft_6455、framing/（Text / Binary / Ping / Pong / Close / Continuous）、handshake/、extensions/permessage_deflate（压缩扩展）、conn/SSLSocketChannel（wss）
  • 二进制帧支持完整：onMessage(ByteBuffer)、send(ByteBuffer)、sendFragmentedFrame
  • 服务端实现：server/WebSocketServer、DefaultWebSocketServerFactory

上层是单例 TDSWebSocketService（com/tds/common/websocket/TDSWebSocketService.java），自带断线重连和心跳：

成员行号作用
TRIM_MAX_TIMES = 6019重连上限 60 次
STATE_OPEN / CLOSING / CLOSED17–191 / 3 / 2
setDestUrl(String, WebSocketConfig)49注入 URL 与 header，并立即 connect()
checkConnection()64断线补连
sendMessage(String)241出站
registerMessageListener(Type, Listener)89按消息类型注册监听
addConnectionStateListener(Listener)97连接状态回调

WebSocketConfig（内部类，L248）只有两个字段：int connectionTimeout 和 Map<String,String> heads——header 就是鉴权 token 的载体。WebSocketConfigBuilder（L280）默认 connectionTimeout = 45 秒。

消息类型枚举只有两个值：MESSAGE_TYPE_TAP_FRIEND / MESSAGE_TYPE_OTHER——说明原始用途是 TapTap 好友服务。

为什么它现在是休眠的

我做了三重验证：grep TDSWebSocketService 在整个 dex 内除自身包外零引用（连反射所需的字符串都没有）；setDestUrl 只出现在定义处；C# 侧字符串常量里也没有这个类名。

结论：它由 Unity 运行时通过 JNI 桥按需唤醒，静态拿不到 URL 和 token。但类本身是完整可用的——这正是方案 A 的立足点。

4.2 死代码 shaded okhttp3

com.tapsdk.antiaddiction.skynet.okhttp3.* 是一份被重打包的 OkHttp 3，WS 部分完整存在（OkHttpClient.newWebSocket() 见 L335、internal/ws/RealWebSocket、WebSocketReader、WebSocketWriter、WebSocketProtocol），但同模块实际调用路径是旁边的 retrofit2 + rest/utils/HttpUtil。

调用者是 AntiAddictionImpl、AntiAddictionUIImpl、MockDataInterceptor——全是防沉迷的 HTTP 接口。WS 部分是死代码。

4.3 无 WS okhttp2 + retrofit

retrofit/client/OkClient.java 引用 com.squareup.okhttp（OkHttp 2.x），只走 HttpURLConnection，超时 15s / 20s。纯 HTTP。

JNI 桥：C# 如何驱动 Java

C# 侧调用 Java 的唯一入口是 Unity 的 AndroidJavaObject，封装在两个工具函数里（dump.cs TypeDefIndex 9987）：

AndroidPluginUtility.GetSingletonInstance(string _className,
                                          string _methodName = "getInstance")   // RVA 0x1C67934
AndroidPluginUtility.CreateClassObject(string _className)                        // RVA 0x1C67BD0

C# 侧字符串常量里出现的 Java 类名，证实了桥的形态：

  • com.tds.common.bridge.Bridge / CommonBridge / BridgeCallback — 通用命令分发
  • com.taptap.sdk.wrapper.TDSLoginService / TDSLoginServiceImpl — 登录

Java 侧对应实现位于 com/tds/common/bridge/（含 command/、result/、annotation/ 子包）。

观察桥的价值

Hook AndroidPluginUtility.GetSingletonInstance 是发现所有 Java 侧 SDK 被唤醒时机的捷径——其中就包括 TDSWebSocketService。如果你想知道游戏是否真的启用了 Java WS，这是最直接的探针。

07

方案 A 复用 Java-WebSocket

推荐路径。不去碰游戏的 LeanCloud 连接，而是把 APK 里已经躺着的那套 RFC6455 实现当成一个通用 WS 库，从 Frida 直接驱动它连你自己的服务器。零移植、零编译、不依赖游戏是否启用了它。

✅ 2026-10-16 已真机验证通过

frida-gadget 路线注入。双向收发、服务端主动推送、heads() 注入的 x-from: frida 握手 header —— 全部实测成功。

实现：network\ws\phigros_ws.js · 服务端：network\ws\ws_server.py · 手册：network\ws\README.md

接口签名（已从源码坐实）

// WebSocketConfigBuilder
public static WebSocketConfigBuilder getBuilder();
public WebSocketConfigBuilder connectTimeOut(int i);
public WebSocketConfigBuilder heads(Map<String, String> map);   // ← 是 heads()，不是 setHeads()
public WebSocketConfig build();

// WebSocketEventListener（注册监听器时实现这 4 个）
void onOpen();   void onMessage(String str);
void onClose(int i, String str, boolean z);   void onError(Exception exc);
两条已确认的关键行为

header 注入链路：WebSocketClient 构造器遍历 config.heads 逐个 addHeader(k, v)，并 setConnectionLostTimeout(config.connectionTimeout)——默认 45 秒自动 ping。

收包安全、发包静默：onMessage 在无监听器时直接 return，不会 NPE；但 sendMessage 在非 OPEN 状态静默丢弃，必须先查 getConnectionState()。

建连 + 发送

// frida -U -f com.PigeonGames.Phigros -l ws_out.js
Java.perform(function () {
  var Svc     = Java.use("com.tds.common.websocket.TDSWebSocketService");
  var Bld     = Java.use("com.tds.common.websocket.TDSWebSocketService$WebSocketConfigBuilder");
  var HashMap = Java.use("java.util.HashMap");

  var heads = HashMap.$new();
  heads.put("X-From", "frida");              // 鉴权 header 走这里

  var cfg = Bld.getBuilder()
               .connectTimeOut(45)
               .heads(heads)                  // ← heads()，不是 setHeads()
               .build();

  var svc = Svc.getInstance();
  svc.setDestUrl("wss://your.host/ws", cfg); // 内部立即 connect()

  setTimeout(function () {
    Java.perform(function () {
      Svc.getInstance().sendMessage(JSON.stringify({ t: "ping", n: 1 }));
    });
  }, 3000);
});

接收

两条路，任选：

// ① 直接挂单例的回调（文本帧）
var Svc = Java.use("com.tds.common.websocket.TDSWebSocketService");
Svc.onMessage.overload("java.lang.String").implementation = function (m) {
  console.log("[WS in] " + m);
  return this.onMessage(m);                  // 转调原实现
};

// ② 挂底层二进制帧
var Base = Java.use("com.tds.common.websocket.client.WebSocketClient");
Base.onMessage.overload("java.nio.ByteBuffer").implementation = function (buf) {
  console.log("[WS bin] " + Java.array("byte", buf.array()));
  return this.onMessage(buf);
};

若要注册自己的监听器，用 Java.registerClass 实现 WebSocketEventListener，再 registerMessageListener(Type, listener)。签名以上面前置脚本的输出为准。

注意事项

  • ws:// 明文可用。NSC（res/8G.xml）里 cleartextTrafficPermitted="true" 明确放行，不受 targetSdk 30 默认限制。实测已通。
  • 自签名 wss:// 也能用。NSC 信任用户 CA（<certificates src="user"/>），且 WebSocketClient 建 SSL 上下文用的是 SSLContext.init(null, null, null)——null TrustManager 走系统默认，会读 NSC。把证书装进 Android 用户证书库即可，无需 root。
  • 线程：WS 回调发生在 Java 子线程，Unity API 只能在主线程调。要回灌游戏需 runOnUiThread 或 UnityPlayer.currentActivity 转发。
  • 生命周期：sendMessage 前确认 getConnectionState() == 1，否则消息会被静默丢弃。重连由 tryTimes 控制，上限 60 次。
  • 不干扰游戏：setDestUrl 会 reset() 掉已有的 client。目前游戏没用这个单例，所以安全；但如果哪天发现它被激活了，用独立的类实例而不是单例。
08

方案 B Hook IL2CPP 的 LeanCloud

方案 A 是「用游戏里的库」，方案 B 是「接管游戏自己的连接」。观察和改写在跑的 LeanCloud 流量走这条。

用 frida-il2cpp-bridge（推荐）

比裸地址稳，不怕版本偏移，直接按类名方法名定位：

import "frida-il2cpp-bridge";

Il2Cpp.perform(() => {
  // 程序集名：DummyDll 显示为 Realtime.dll（待确认）
  const k = Il2Cpp.domain
    .assembly("Realtime")
    .image.class("LeanCloud.Realtime.Internal.WebSocket.LCWebSocketClient");

  // 出站
  k.method("Send").overload("System.String").implementation = function (text) {
    console.log("[LC →] " + text);
    return this.method("Send").overload("System.String").invoke(text);
  };

  // 建连上下文：server / subProtocol / headers / keepAliveInterval
  k.method("Connect").implementation = function (server, subProto, headers, keepAlive) {
    console.log("[LC connect] " + server + "  proto=" + subProto);
    console.log("[LC headers] " + headers.toString());
    return this.method("Connect").invoke(server, subProto, headers, keepAlive);
  };
});
程序集名待定

DummyDll 里唯一与 LeanCloud 相关的是 Realtime.dll，但命名空间是 LeanCloud.Realtime.*，两者是否对应需要实际加载时确认。用 Il2Cpp.domain.assemblies 遍历一次即可定论。

裸 Interceptor（不依赖第三方库）

const base = Module.findBaseAddress("libil2cpp.so");

// IL2CPP 字符串：klass(8) monitor(8) length(4) chars(2×len)
function readIl2CppString(p) {
  if (p.isNull()) return null;
  const len = p.add(0x10).readS32();
  return p.add(0x14).readUtf16String(len);
}

Interceptor.attach(base.add(0x3552F54), {          // Send(string)
  onEnter(args) {
    // args[0]=this  args[1]=Il2CppString*  args[2]=MethodInfo*
    console.log("[LC →] " + readIl2CppString(args[1]));
  }
});

Interceptor.attach(base.add(0x35530EC), {          // StartReceive()
  onEnter() { console.log("[LC] StartReceive 触发"); }
});

地址校验：0x3552F54 是 ELF 虚拟地址，运行时地址 = libil2cpp.so 基址 + VA（前提是首个 PT_LOAD 的 vaddr 为 0）。挂之前先 base.add(0x3552F54).readU32() 看是否是合理指令字，别盲挂。

入站怎么拿

StartReceive() 是一个异步循环，读 OnMessage 字段（@0x10）更直接——它是 Action<byte[], int>，挂在实例上。先用 bridge 拿到 LCWebSocketClient 的实例，再读字段：

const inst = k./* 从 Connect 的 this 捕获 */;
const cb = inst.field("OnMessage").value;   // Action<byte[], int>
// 或将 callback 替换为自己的实现，转发原始调用
风险

IL2CPP 方法是编译后的 C++，参数是 Il2CppObject*，没有类型信息。Send(string) 这种简单签名没问题；一旦涉及泛型共享（generic sharing）或值类型参数，裸 hook 极易读错。复杂场景请用 bridge。
